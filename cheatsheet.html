Quick Decision: What to Use

Need it in 2 seconds, good quality?   →  groq "..."         (gpt-oss-120b, free)
Private data / offline / instant?     →  ask "..."          (local 3B GPU)
Best local quality, still private?    →  gemma (interactive) (4B GPU)
Coding session with file access?      →  p  or  pask "..."  (Pi + Groq)
Spotify / scheduling / web search?    →  h  or  hask "..."  (Hermes — BROKEN, 413)
Browse & chat with history?           →  localhost:8080      (OpenWebUI)
Which of my services are up?          →  links               (clickable URLs)
Edit code with real LSP?              →  v <file>            (nvim + pyright/ruff)
Record a terminal demo for a post?    →  rec <name>          (cast + GIF)
What is making the box slow?          →  sysload             (load, hogs, orphans)

groq — Your Workhorse (gpt-oss-120b, free)

# Direct prompts
groq "write a blog post about X"
groq "proposal email to [client] for [project]"
groq "5 LinkedIn posts about web design for Kenyan SMEs"
groq "reply to this client complaint professionally: [paste]"

# Pipe content in (for analysis / review)
cat file.txt | groq "summarise this"
head -50 index.html | groq-review "review meta tags for SEO"
cat contract.txt | groq "what are the key risks in this?"

# Save directly to file
groq "write SEO post about mobile websites in Kenya" > ~/content/draft.md
groq "write 10 email subject lines for a website launch offer" >> ~/content/subjects.txt

# Fast model (lighter tasks, even quicker)
groq-fast "give me 3 tagline options for a web agency"

Limits: 14,400 req/day · ~30 req/min · No system prompt overhead

Errors are no longer silent. If the model id ever dies again you will see groq: <message> rather than empty output.

Editor — Neovim

v file.py            # alias for nvim (also `vi`)
nvim .               # opens the oil file browser at cwd

Rebuilt 2026-09-09. Neovim 0.12 native LSP (no lspconfig framework calls), treesitter highlighting, pyright pointed at each project's own .venv, ruff for lint + format. Modular config under ~/.config/nvim/lua/; full key reference in ~/.config/nvim/README.md.

Keys (leader = space) Does
<space>ff fg fb fr files · grep · buffers · recent
- file browser at the current file's directory
<space>cf ca cr format · code action · rename
<space>gg lazygit, floating
<space>gs gr · ]h [h stage hunk · reset hunk · next/prev hunk
<space>dr dm dM ds dt manage.py runserver · migrate · makemigrations · shell · test
<space>xx every diagnostic in the project (trouble)
gd · K · ]d [d definition · hover · next/prev diagnostic
<C-\> floating terminal

Django-aware: any .html under templates/ is forced to htmldjango (emmet, auto tag-close, djlint), and the <space>d* keys run uv run python manage.py from whichever manage.py sits above the current file — works in CES platform/ and in the WSA repo without cd-ing first. The statusline shows which .venv pyright resolved.

:Lazy                 " plugin status / update
:MasonToolsInstall    " reinstall servers + formatters (new machine)
:checkhealth          " diagnose
:ConformInfo          " which formatter runs in this buffer

Terminal font is JetBrainsMono NFM (Nerd Font, installed 2026-09-09) — icons come from that. If glyphs ever render as boxes, set vim.g.have_nerd_font = false in ~/.config/nvim/lua/config/options.lua and everything falls back to ASCII.

Recording Demos — asciinema

For blog posts, insights drafts and client walkthroughs. rec records the session and converts it to a GIF in one go.

rec django-deploy    # → ~/recordings/django-deploy-<stamp>.cast + .gif
                     #   stop with Ctrl+D or `exit`
recordings           # list recordings, newest first

# manual control
asciinema rec demo.cast --overwrite --title "demo"
asciinema play demo.cast                  # replay in the terminal
asciinema upload demo.cast                # public link on asciinema.org
agg demo.cast demo.gif --font-size 14 --speed 1.5 --theme monokai

Resize the pane to ~100 columns before recording — a full-width capture is unreadable once embedded in a post. rec prints a ready-made <img> embed snippet when it finishes, pointing at /recordings/<slug>.gif.

sshd on this box is key-only since 2026-09-09 (PasswordAuthentication no in /etc/ssh/sshd_config.d/crafted.conf). Any new device must have its pubkey appended to ~/.ssh/authorized_keys first — a password will not get you in. To re-enable temporarily: sudo sed -i 's/^PasswordAuthentication no/PasswordAuthentication yes/' /etc/ssh/sshd_config.d/crafted.conf && sudo systemctl reload ssh

sysload      # What is slow RIGHT NOW: load vs cores, real available RAM,
             # top CPU/RAM hogs, zellij session count, orphaned agent processes
reap         # Prune dead zellij sessions + orphaned agents (PPID==1), then show log
reap-dry     # Same, report only — changes nothing
reaplog      # Reaper history

ports        # Port registry: every known service, its port, and up/down
freeport     # Free a port that something is squatting on

watch -n10 --color ces-crawl   # Command-centre dashboard (the Zellij Boss tab)

This box runs a lot at once — Docker stacks, Ollama, agents. A load average above ~8 on 4 threads means everything, editors included, will feel slow; sysload tells you which process to kill first.

links probes each known port and prints only what is listening, so it doubles as an up/down check. It uses OSC 8 terminal hyperlinks — Windows Terminal, WezTerm, VS Code and iTerm2 render them clickable; anywhere else you still get the plain URL. links -t needs tailscale serve running for that port.
